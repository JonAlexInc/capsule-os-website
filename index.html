      WHY CAPSULES?

      Keep the application.
      Lose some of the setup.

      Old software often needs a particular environment. New software often asks for more access than you expect. Capsule OS explores one place to manage both.

      A capsule pairs an application with a configured runtime. The desktop aims to make launching feel ordinary while keeping the runtime, permissions, and diagnostics visible when you need them.

      EXPRESSION WITH VISIBLE BOUNDARIES

      Make the desktop personal.
      Keep access understandable.

      Material Studio turns finish, depth, icon language, motion and surface treatment into a coordinated system choice. Paper samples cotton stock and carries its fiber and letterpress treatment through native file objects; material profiles can also choose dock, top-bar and Super Menu construction separately. Named layouts carry that expression through the desktop.

      That freedom sits beside explicit application grants, separate runtimes and readable diagnostics. Capsule OS is exploring how an expressive computer can still show which files, devices and network access an application receives.

      before you get attached.

      CURRENT LIMITATION

      Very large text can exceed a small Properties window.

      The current layout guards hide an unusable search field, but the source still records a minimum-window-size problem at 300% text scale. This site does not establish native accessibility conformance.

      KNOWN RISK · INSTALLER

      Duplicate partition labels can target the wrong disk.

      The installer resolves partitions using global Capsule partition labels. The latest ledger flags ambiguity when multiple disks have those labels. Real-disk installation remains unverified; this preview provides no installation or disk-writing action.

      Source note S5 ↗

      MITIGATION · RETEST NEEDED

      VMware display behavior needs fresh verification.

      The latest build notes describe disabling direct scanout for VMware as a blink mitigation. Confirmation in VMware is still needed. Recorded QEMU boot success does not establish VMware graphics or bare-metal reliability.

      Source note S5 ↗
      03
      NOT A COMPATIBILITY PROMISE

      A runtime definition is only a starting point.

      The tree includes Windows, DOS, native Linux, and other runtime definitions. Their presence does not prove a particular application, device, game, or installer works. No compatibility score or performance benchmark is claimed here.

      Source note S6 ↗
      04
      OLDER REPORT SUPERSEDED

      Two historical sandbox/startup reports have code changes.

      The launcher now includes a cleared environment; the startup capsule array is now 256 entries, replacing the old 32-entry array. Older reports of inherited session variables and silently dropping the 33rd capsule should not be repeated as unchanged current bugs. This is source inspection, not a security audit.

      Source note S7 ↗
      05
      SECURITY EXCEPTION

      A native runtime disables WebKit’s internal sandbox.

      The deb-app runtime definition sets WebKit’s sandbox-disable environment flag. The outer capsule boundary is a separate mechanism; it is not a reason to describe this configuration as fully sandboxed or security-audited.

      S1 · Appearance & design

      shared/theme.c defines the exact Midnight, Paper, Carbon Blue, and Sea Glass color roles used in the demo. docs/DESIGN.md explains the design principles. Browser layout and wallpaper are illustrative.

      S2 · Permission changes & relaunch

      panel/src/capsule-permissions.c, tools/capsule-run, and docs/manual/permissions.md describe saved grants and their use at launch. The demo models three switches and a successful relaunch, not real enforcement or all failure paths.

      S3 · Launch diagnostics

      panel/src/capsule-logs.c includes “Only those lines” and log-export controls. tools/capsule-run writes launch records. All log entries on this page are invented demo data.

      S4 · Large-text layout limitation

      See the comment and guard around tab_has_search(a->tab) && page_bottom(a) > page_top(a) in panel/src/capsule-permissions.c. The native UI has not been reproduced in a VM for this review.

      S5 · Installer risk & VMware verification

      tools/capsule-install-run resolves /dev/disk/by-partlabel/capsule-*. capsule-ledger/NOTES.md, entry 135, and capsule-ledger/briefs/controller-home-and-imports.md record the duplicate-label risk, VMware mitigation, and limits of build 202609090239 testing. Earlier launch failures and console flashes have later fix records and are not listed as unchanged bugs here.

      S6–S7 · Runtime scope & changed code

      runtime-defs/ contains runtime definitions. In current source, tools/capsule-run includes --clearenv and compositor/src/capsule-wm.c declares pending_capsules[256]. Historical documentation still describes some earlier behavior.

      S8 · Native runtime sandbox exception

      runtime-defs/deb-app.json sets WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS to 1. Ledger entry 133 explicitly leaves this exception open. This inspection does not evaluate the overall security of the OS.

      S9 · Library empty-state route

      panel/src/capsule-library.c displays “Install adds one from a file you already have” and registers HIT_INSTALL; its install helper invokes capsule-install. The current native empty-state capture shows the wording. The OS was not changed during this website task.

      S10 · Material Studio & semantic icons

      panel/src/capsule-settings.c, shared/iconprofile.c, shared/fileglyph.c, tools/capsule-icon-packs and the shipped registry implement the current page, shared profile, semantic renderer, material-aware application plates and validated data-only extension boundary. Focused tests cover the implemented source, not every third-party package’s metadata.

      S11 · Media Surface

      panel/src/capsule-player.c, panel/src/capsule-media-worker.c, shared/mediaframe.h, panel/src/capsule-panel.c and the compositor protocol implement the controller, exact-file decoder boundary, embedded video exchange, PiP/fullscreen states and desktop-control bridge. tools/check-media.sh exercises state, grants, recording, frames and controls without claiming unavailable hardware validation.

      S12 · Whole-shell layouts & rich Peek

      panel/src/capsule-launcher.c, panel/src/capsule-panel.c and tools/capsule-layout implement the named whole-shell layout model and its spatial editor. Commit c5c77bd passes shared Save/Done, native descriptor routing, layout-return and interrupted-edit gates; 422901a passes board movement, resizing, anchored menus and descriptor import gates. panel/src/capsule-files.c and tools/capsule-peek implement bounded rich previews. Guest pointer feel remains unverified for this newer revision.

      S13 · SMB, SFTP & FTP network files

      panel/src/capsule-files.c owns the mapping flow and panel/src/capsule-smbfs.c provides the FUSE/libSMBclient Windows-share helper. Build and VM-injection gates require that helper instead of shipping a dead SMB choice. See the source map for exact commits and limitations.

      S14 · Library sofa route

      panel/src/library-sofa.h, panel/src/capsule-library.c, tools/library-sofa-test.py and tools/library-sofa-live-test.py cover the controller-first route, bounded catalogue handling and isolated fictional demo. This site has no new VM screenshot or deployed-build receipt for the rewrite yet.

      S15 · Launch-protocol build gate

      Commit eaaab20 runs tools/wayland-launch-protocol-test.py before a compositor receipt is issued. It verifies required Wayland registries and a subsurface path in the build result. This narrows a launch-regression class; it does not certify every guest application launch.

      S16 · Material World 07 installed-image verification

      Source 293b4a3 was installed under stamp 20260922-material-world-07. A separate read-only verifier matched 402 exact installed hashes, resolved 35 Capsule ELFs through both A/B slots and found rich-preview helpers present. This proves the recorded offline image state, not a guest visual pass, hardware behavior or application compatibility. The Paper and Jelly gallery images remain source renders.

      S17 · Current source systems and host gates

      Current source adds refined material bounds, authored icon languages, a textured 2.5D Aquarium and Library Coverwall/fullscreen return. The host gates are source/headless or compositor-client evidence. They do not establish all-world visual approval, a full 3D Aquarium or full tank editor, or refreshed guest interaction acceptance.
